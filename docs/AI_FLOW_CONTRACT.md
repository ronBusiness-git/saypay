# SayPay – AI Payment Flow Contract (shared by all agents)

Stack: Next.js 16 App Router, **plain JavaScript only (no TypeScript)**, Tailwind, Mongoose (`src/lib/db.js` → `connectDB`), Groq LLM via `process.env.GROQ_API_KEY` / `GROQ_MODEL` (=`openai/gpt-oss-120b`, OpenAI-compatible endpoint `https://api.groq.com/openai/v1/chat/completions`). Imports use `@/lib/...` alias in API routes. No new npm packages.

## Product story (PayPal AI hackathon)
User talks (voice or text) to SayPay Assist. AI understands intent, finds the bill in the database (seller invoices = the "payment request", like PayPal invoicing), verifies it with the deterministic MatchCheck safety engine, shows a **pre-filled payment card**, and the **human** clicks **Pay with PayPal** (1 click). Receipt appears inline. 3 steps max: **Say → Review (pre-filled, verified) → Pay**.

## Models (owned by Backend-Auth agent)
`User`: `{ userId, email (unique, lowercase), name, role: 'buyer'|'seller', passwordHash, passwordSalt, merchantKey|null, createdAt }` — hash with `crypto.scryptSync`.

`Invoice`: `{ invoiceId (e.g. 'GL-1042'), merchantKey, merchantName, buyerEmail, amount: '12.50' (string, 2dp), currency 'USD', description, dueDate (Date), status: 'UNPAID'|'PAID'|'CANCELLED', transactionId|null, checkId|null, createdAt }`.

## Auth API (Backend-Auth agent)
- `POST /api/auth/login` `{email,password}` → 200 `{ user:{userId,email,name,role,merchantKey} }` + httpOnly cookie `saypay_session` (HMAC-signed, secret `process.env.SESSION_SECRET || 'saypay-dev-secret'`). 401 `{error}` on bad creds.
- `POST /api/auth/signup` `{name,email,password,role}` → same as login.
- `POST /api/auth/logout` → clears cookie.
- `GET /api/auth/me` → `{ user }` or 401.
- Helper `src/lib/session.js`: `getSessionUser(request)` (reads cookie from `request.headers` / `next/headers` cookies) usable by other routes.
- Route protection: unauthenticated visits to app pages redirect to `/login` (use `src/proxy.js` for Next 16, or `middleware.js` if proxy unsupported). `/login`, `/signup`, `/api/auth/*`, static assets excluded.

## Data APIs (Backend-Auth agent)
- `GET /api/invoices?status=UNPAID` → `{ invoices:[Invoice] }` scoped to session buyer (or seller's merchantKey for seller).
- `GET /api/dashboard/stats` → `{ totals:{checks,clear,review,blocked,completedPayments,volumeMinor,unpaidInvoices,unpaidMinor}, daily:[{date:'YYYY-MM-DD',checks,clear,review,blocked,volumeMinor}] (last 7 days), recent:[{id,timestamp,counterparty,amount,status,paymentStatus,href}] }` from real PaymentCheck/Transaction/Invoice collections.
- Invoice gets marked `PAID` (with transactionId) when `POST /api/paypal/capture-order` completes for a check whose `PaymentCheck.invoiceId` is set (add optional `invoiceId` field to PaymentCheck schema).

## Assistant API (AI-Backend agent)
`POST /api/assistant` body `{ messages:[{role:'user'|'assistant', content}], context?:{ selectedInvoiceId? } }`
Response:
```json
{
  "reply": "natural language, short, warm, speakable (1-2 sentences)",
  "action": "none" | "show_invoices" | "prepare_payment" | "need_info" | "show_history",
  "data": {
    "invoices": [Invoice],                    // for show_invoices
    "payment": {                              // for prepare_payment (already MatchCheck-verified)
      "checkId": "uuid", "status": "CLEAR|REVIEW|BLOCKED", "canCreateOrder": true,
      "invoiceId": "GL-1042", "merchantName": "GreenLeaf Demo Store", "merchantKey": "...",
      "amount": "12.50", "currency": "USD", "description": "...", "reasonCodes": [],
      "checks": { "recipient":{...}, "amount":{...}, ... }
    },
    "transactions": [ ... ]                   // for show_history
  }
}
```
Behaviour: LLM decides intent (greeting/small talk → friendly reply, action none; "show unpaid invoices/bills" → show_invoices; "pay GreenLeaf" / "pay invoice GL-1042" / "pay the 12.50 bill" → find matching UNPAID invoice of the user, run `runMatchCheck` (intent = what user said, request = DB invoice), persist PaymentCheck with invoiceId, return prepare_payment; ambiguous → need_info asking a short question). Replies are generated by the LLM, never canned. AI never pays; the human clicks Pay. Fallback if Groq fails: Gemini (`src/lib/gemini.js`) then a small rule-based reply.

## Frontend (two agents)
- Assistant page `/new-check` (Frontend-Assistant agent): left = chat (voice + text, always ready), right = context panel (invoice list / pre-filled verified payment card with **Pay with PayPal** button / inline receipt). Uses `/api/assistant`, `/api/paypal/create-order`, `/api/paypal/capture-order`.
- Login/Signup/Dashboard/Shell (Frontend-Shell agent): real auth, buyer/seller quick sign-in, real dashboard data + charts, remove demo badges / "Back to dashboard" / Demo Lab clutter, humanized copy, user menu with logout.
